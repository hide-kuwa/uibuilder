## Ops Notes（append-only, 2025-09-08）

本リポジトリの「軽量運用」メモ。既存行は変更せず **追記のみ** を原則とする。

### SWR の peerDependencies 警告について
運用方針：
- ビルド/実行に影響のない `peer dep missing: swr` などの警告は **許容**（無視）する。
- 当面は `@tanstack/react-query` を正式採用、`swr` は **未使用**。不要依存は追加しない。
- ただし以下のいずれかが発生した場合は対応を検討：
  - CI/本番で **ビルド失敗に昇格**（warning→error）
  - 警告が 1 画面（~20行）を超えて **可読性を著しく阻害**
対応手段（どれも append-only）：
  1) 警告発生パッケージを切り分けて subpath build 順序を調整（`@chizu/ui → @chizu/registry → @chizu/renderer`）
  2) `package.json` に **説明コメントの追記**（依存追加は原則しない）

### 最小テスト導入のトリガ（バグ兆候ベース）
以下のいずれかが **直近7日で2回以上** 発生したら、スモークテストを **最小スコープ** で導入する：

### スモークテストの最小スコープ（導入時メモ）
目的：**画面が開く＋主要イベントが1つ流れる** だけを確認。E2E 網羅は行わない。
チェック観点：
1) Preview：`/dev/pages` が開く
2) Export：`/dev/export` → ZIP作成 → `manifest.contentHash` が画面表示値と一致
3) Events：`/events` に 1行以上イベントが流れる（ハートビート含む）
4) Autosave：バッジ **Queue → OK** 遷移が1回発生
実装メモ：
- テストコードは `apps/*/test/smoke/*.spec.ts` に **新規追加のみ**（既存行は変更しない）
- 依存は追加せず、既存の devServer/API を **直叩き**（Playwright 等の導入は保留）

### 既知のビルド順序
`@chizu/ui` → `@chizu/registry` → `@chizu/renderer` の順で subpaths を生成。  
コマンド例：
```bash
pnpm -r --filter @chizu/types --filter @chizu/ui --filter @chizu/registry --filter @chizu/renderer typecheck
pnpm -r --filter @chizu/types --filter @chizu/ui --filter @chizu/registry --filter @chizu/renderer build
pnpm -F @chizu/ui run build     # subpaths 再生成
```
